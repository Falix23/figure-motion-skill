# 产物告知与清单

每次交付先说明：视频时长、音色、视频生成是否已完成及验证范围。随后给出保存环境与完整目录，以及实际产物表。

建议用户可读表列：文件或目录、用途、机器与完整路径、观看/下载链接。文件共享同一目录时可在回复中先给完整目录再列文件名，逐文件绝对路径仍写入清单。音视频、字幕、口播稿和工程源码须单列；分段、截图、字体与日志可分组，但给出文件数量与用途。链接必须来自实际存在且可访问的文件，不用猜测路径。

扫描命令：

```sh
python3 scripts/inventory_artifacts.py /work/video --host "远程开发机（ssh localhost）"
```

artifacts.json 的 files 每项记录 role、host、path、relative_path、bytes、sha256。artifacts.md 展示同一清单。两个清单自身不递归纳入摘要；__pycache__ 不作为交付文件，符号链接单列而不跟随读取。自动角色分类后仍要核对。

外部缓存通过 `--retained retained-assets.json` 明确传入，格式为条目数组，例如：

```json
[{"role":"共享依赖环境","host":"远程开发机","path":"/work/.venv","status":"沿用，非本次新增","purpose":"运行配音与渲染脚本"}]
```

不要扫描全用户目录或密钥文件以寻找缓存。只检查任务已知的位置；清单不能含凭据。若模型缓存体积较大，说明大小及本次是否实际使用。目录仍被其他作品使用时不宣称可直接删除。

远程模式示例措辞：

“以下生成的工作文件保存在远程开发机；我未将它们同步或下载到你的Mac工作目录。用户自行下载和浏览器缓存不在本次清单核查范围内。新增输出目录为完整绝对路径。播放页和下载链接通过当前端口转发访问，关闭服务或端口转发后链接可能失效；远程文件仍保留。”

已有旧版和试音与新目录分开列出；正文交付表与逐文件清单同时提供。后续清理只按用户指令进行。
